# Компилятор Funny для JVM

Компилятор читает модуль `.funny` и создаёт один `public final` класс. Каждая функция Funny становится `public static` методом с тем же именем. Байт-код генерируется из оптимизированного трёхадресного IR через JDK Class-File API.

## Сборка и запуск

Нужны JDK 25 и Maven. Команды выполняются из корня репозитория.

```sh
mvn -f parser/pom.xml clean test
mvn -f IRandOptimizations/pom.xml clean package

funny_jar=IRandOptimizations/target/funny.jar
funny_demo=IRandOptimizations/examples/demo.funny
funny_out=IRandOptimizations/target/demo

java -jar "$funny_jar" compile --out "$funny_out" "$funny_demo"
java -jar "$funny_jar" run --out "$funny_out" "$funny_demo" factorial 5
java -jar "$funny_jar" run --out "$funny_out" "$funny_demo" details '[2, -3, 4]' 1
java -jar "$funny_jar" run --out "$funny_out" "$funny_demo" updated '[2, -3, 4]' 1 9
```

`compile` печатает путь к `demo.class`. Три вызова `run` печатают `120`, `[-3, -2, 3]` и `[2, 9, 4]`. Каждый `run` также записывает класс и вызывает выбранный метод на JVM. Целые аргументы передаются отдельными словами, массив передаётся одним аргументом в квадратных скобках. Пустой массив записывается как `'[]'`.

Опции указываются перед именем файла. `--out` задаёт каталог, по умолчанию используется текущий. `--class` задаёт простое имя JVM-класса. По умолчанию оно берётся из имени файла без `.funny`, символы вне `[A-Za-z0-9_]` заменяются на `_`, перед начальной цифрой добавляется `_`. `--no-opt` отключает оптимизации. Для просмотра дескрипторов и инструкций используйте `javap -classpath "$funny_out" -s -c demo`.

Коды завершения CLI приведены в таблице.

| Код | Значение |
| --- | --- |
| `0` | Успех |
| `1` | Ошибка компиляции, диагностика в `stderr` |
| `2` | Ошибка аргументов CLI или файлового ввода-вывода |
| `3` | Исключение JVM при запуске, исходный класс исключения и стек в `stderr` |

## T0 и T1

ДКА распознаёт токены с позициями, парсер строит AST рекурсивным спуском. Запись `b[i] = v` представлена узлом `Update`, который печатается как `(assign (targets b) (set b i v))`. Параметры и результаты требуют аннотаций типов. Тип локальной без аннотации фиксирует первое корректное присваивание. Эталонные тесты сравнивают токены, AST, обессахаренную запись и синтаксические диагностики. [Грамматика](parser/grammar.ebnf), [формат AST](parser/README.md#аннотированный-ast).

Семантический анализ проверяет имена, типы, аргументы и арность присваивания. Запись в параметр, включая `a[i] = v` для параметра `a`, даёт позиционную ошибку `IMMUTABLE_PARAMETER`. Анализ связывает вызовы по сигнатурам до проверки тел, поэтому поддерживает рекурсию и вызовы вперёд.

IR разделяется на базовые блоки и CFG. Оптимизатор распространяет и сворачивает константы, применяет алгебраические упрощения и удаляет мёртвые присваивания с учётом живости. Вызовы и операции, способные бросить исключение, сохраняются. В байт-коде арифметика использует инструкции JVM для `int`, ветвления и циклы соответствуют переходам IR. `and`, `or` и `->` вычисляют правый операнд только при необходимости. [Формат TAC, CFG и примеры](IRandOptimizations/README.md#формат-ir).

## Финал и ABI

| Сигнатура Funny | Представление JVM |
| --- | --- |
| Параметр или единственный результат `int` | `int`, дескриптор `I` |
| Параметр или единственный результат `int[]` | `ru.nsu.naboka.runtime.ImmutableIntArray` |
| Два и более результатов типа `int` | Новый `int[]` длины `returns`, дескриптор `[I` |

`ImmutableIntArray` поставляется в `funny.jar`. При вызове из Java добавьте каталог с `.class` и этот JAR в classpath. Фабрики `of` и `copyOf` копируют входной `int[]`. Присваивание `b = a` сохраняет ссылку на неизменяемый объект. Обновление `b[i] = v` вызывает `b.with(i, v)`, который копирует внутренний массив и меняет элемент копии. Новая ссылка записывается в `b`, а прежние ссылки продолжают указывать на исходный объект. Равенство массивов сравнивает их элементы.

При многозначном возврате метод записывает элементы в новый `int[]` в порядке `returns`. Вызывающий метод сначала вычисляет аргументы и выполняет вызов, затем читает элементы результата слева направо и записывает их в цели. Позиционная ошибка `JVM_TUPLE_TYPE` сообщает о массиве внутри кортежа, поскольку ячейка ABI-кортежа имеет тип JVM `int`.

Проверку деления на ноль выполняет инструкция `idiv`. `get` и `with` полагаются на проверку индекса при доступе к Java-массиву. Таким образом, наружу выходят `ArithmeticException` и `ArrayIndexOutOfBoundsException` соответственно. Значения по умолчанию для явно типизированных локальных и именованных результатов берутся из IR (`0` для `int`, `null` для массива). Разыменование такого массива даёт `NullPointerException`.

`requires`, `ensures`, `invariant`, `assert` и `assume` проходят разбор и проверку имён и типов как аннотации. Кванторы поддерживаются в рамках аннотаций. Формулы без кванторов, используемые в исполняемых выражениях, компилируются в закрытые вспомогательные методы. Верификация аннотаций и проверки их истинности отложены как бонусы.

## Проверка результата

Тесты JVM загружают и исполняют именно сгенерированные классы. Они сравнивают результаты с включёнными и отключёнными оптимизациями, проверяют сигнатуры ABI, рекурсию, короткое замыкание, массивы, кортежные вызовы, встроенные контракты как синтаксис, ошибки компиляции и исходные исключения JVM. [Тесты JVM](IRandOptimizations/src/test/java/ru/nsu/naboka/jvm/JvmCompilerTest.java).

```sh
mvn -f IRandOptimizations/pom.xml -DargLine=-Xverify:all test
java -Xverify:all -jar "$funny_jar" run --out "$funny_out" "$funny_demo" divide 9 0
java -Xverify:all -jar "$funny_jar" run --out "$funny_out" "$funny_demo" updated '[]' 0 1
```

Две последние команды завершаются с кодом `3` и печатают `ArithmeticException` и `ArrayIndexOutOfBoundsException` соответственно.
