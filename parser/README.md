# Парсер Funny

Java 17, рекурсивный спуск, AST и восстановление после ошибок. Новый код состоит из шести файлов, без комментариев и без зависимостей времени выполнения. JUnit нужен только для тестов.

## Запуск

Из папки `parser`:

```sh
mvn test
java -cp target/classes ru.nsu.naboka.Main examples/positive.funny
java -cp target/classes ru.nsu.naboka.Main < examples/minimal.funny
```

Без аргументов читается стандартный ввод, с одним аргументом — файл UTF-8. В stdout выводится AST в S-выражениях. Например, `1 + 2 * 3` превращается в `(+ 1 (* 2 3))`. Диагностики идут в stderr в формате `строка:столбец: сообщение`. Коды завершения: 0 — успех, 1 — ошибки языка, 2 — неверные аргументы или ошибка чтения файла.

| Файл | Назначение |

| `grammar.ebnf` | Финальная грамматика и правила разбора |

## Интеграция с первой работой

Maven компилирует исходники текущего модуля и соседнего `../regex_dfa/main/java`. Папки `parser` и `regex_dfa` должны лежать рядом. Код построения автоматов не скопирован и не изменён: используются `RegexToNFA`, `NFA`, `SubsetConstruction`, `Hopcroft`, `DFA`, `TokenSpec`.

Лексер один раз строит минимизированный ДКА по правилам Funny, затем сканирует с максимальным совпадением и запоминанием последнего принимающего состояния. Старая JSON-таблица не подходит целиком: в HW2 добавились `:`, `;`, `|`, `=>`, `->` и новые ключевые слова. Пробелы и комментарии пропускаются с учётом позиций. EOF — отдельный токен. Смещения отсчитываются от 0, строки и столбцы — от 1; CRLF считается одним переводом строки, табуляция — одним столбцом.

Идентификаторы соответствуют добавленной спецификации: латинская буква, далее буквы и цифры. Подчёркивания, разрешённые в HW1, здесь не допускаются. Правило целых чисел сохранено из HW1: `0|[1-9][0-9]*`; `01` даёт два токена и отклоняется при разборе выражения. Алфавит — ASCII, неподдерживаемый символ вызывает диагностику и пропускается.

## Особенности грамматики

Основная форма функции — `f(x: int) returns r: int { ... }`, как в спецификации. Дополнительно разрешено `function f(...)`, чтобы сохранить совместимость с HW1. Формулы имеют вид `p(x: int) => x > 0`; после определения можно поставить `;`, хотя спецификация его не требует. Пропущенные `requires` и `invariant` заменяются на `true`, пропущенное `ensures` — на `false`. Если ключевое слово контракта написано, после него нужен предикат.

Выражения разбираются по уровням приоритета с одним текущим токеном. Общий разбор выражений устраняет конфликт между `(x + 1) < 5` и `(x < 5)`. После построения поддерева проверяется его синтаксическая категория: арифметика, условие или предикат. Например, `r = true`, `if (p())` и импликация в `assert` отклоняются. В условиях разрешена импликация, в предикатах — ссылки на формулы и кванторы. Узел `Call` означает вызов функции в арифметике и ссылку на формулу в предикате; разрешение имён относится к семантическому анализу.

`else` относится к ближайшему незавершённому `if`. Этот известный конфликт исходной грамматики решается явным правилом выбора; полный синтаксис с необязательным `else` не объявляется формально LL(1). Остальной разбор предиктивный, без перебора альтернатив и отката.

`a[i] = v` сразу преобразуется в присваивание `a = set(a, i, v)`: в AST появляется узел `Update`, который принтер показывает как `set`. Он обозначает новый массив, а не изменение старого. Вложенное обновление преобразуется в `a = set(a, i, set(a[i], j, v))`; его допустимость по типам проверяется позже. `set` — внутренний узел AST, а не добавленная функция языка.

Проверка типов, существования и уникальности имён, неизменяемости параметров, числа результатов вызова и вывода типов локальных переменных относится к следующим этапам. Парсер не выполняет программу.

## Ошибки и тесты

После ошибки внутри блока пропускаются токены до `;`, `}`, начала управляющего оператора либо следующего определения. На верхнем уровне разбор продолжается с определения функции или формулы. При ошибках AST может содержать только успешно разобранные части; его нельзя считать корректной программой.

`mvn test` проверяет все операторы, формулы, кванторы, контракты по умолчанию, групповые присваивания, обновление массивов, приоритеты, ассоциативность, позиции с CR/LF/CRLF, границы ключевых слов, максимальное совпадение, пустой ввод и ошибки скобок/типовых аннотаций/операторов. AST минимальной программы сравнивается с `examples/minimal.ast`. Для ошибочного `examples/negative.funny` ожидаются диагностики из `examples/negative.errors`. Есть проверка восстановления и 500 случайных повреждённых входов с ограничением времени.

Для знакомства с реализацией удобно читать файлы в порядке: `Token`, `Lexer`, `Ast`, `Parser`, `AstPrinter`, `Main`.
